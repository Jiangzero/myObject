# Critical Section Analyzer

分析共享全局变量上哪些**访问点**需要临界区保护，并输出分析结论后实施修改。核心判定是**按访问点（per-access）逐条判断，而不是按变量整体判断**。

## 判定规则（核心）

1. **一个全局变量“需要临界区” ≠ 所有用到它的地方都需要**。
2. **单一原子操作不需要临界区**：单条指令完成的对齐读/写（如 32 位 MCU 上单字段赋值 `var = x;`、单字段读取 `y = var;`）。
3. **非原子操作需要临界区**：
   - READ-MODIFY-WRITE：`var++;`、`var += n;`、`var = var + 1;`、`var |= bit;`（读、改、写至少两个指令）。
   - 跨多行代码对同一变量的组合操作：先读多个字段做判断，再依次写多个字段。
   - 必须先验证现场再修改现场（如"若 X 有效则更新 Y"，读取与写入分离）。
4. **不判定为需要的情况**：
   - 访问点在 ISR 上下文（见下）。
   - 操作只落在本通道数组元素，且无任何跨上下文写者。
   - 存在时序保证（如：所有配置字段在硬件使能/中断使能之前写入完成，ISR 触发时配置必然完整）。

## 前置分析

### 1. 枚举共享全局变量
列出被任务级 API 和 ISR 私有函数共享的全部全局变量（常见形态：`Icu_PubXxx[Channel]` 通道数组、状态标志、模式变量）。

### 2. 枚举每个变量的所有访问点
逐个访问点记录：文件、函数、行号、读/写、操作形态（单条赋值 / 复合运算 / 跨行组合）。

### 3. 上下文分类
- **任务级 API**：可以被更高优先级任务抢占。
- **ISR 私有函数**：中断上下文。
- **多核**：另一核同时访问同一变量。

### 4. 竞态判定（按通道按访问点）
- 基于通道的数组元素：**不同通道互不干扰**，只分析同通道访问。
- 构成竞态的必要条件：**同一变量 + 同一通道（或非通道共享变量）+ 至少一个写者 + 访问发生在不同上下文**。
- 通道元素读写只在 "任务级 API 与 ISR 私有函数"、"两个核" 之间才会交叉；ISR 与 ISR 之间按非嵌套中断设计处理。

## 上下文约束

1. **ISR 上下文禁止使用临界区**：会形成临界区嵌套、拉长中断响应。ISR 侧的共享变量安全依赖时序设计而非锁。
2. 时序设计：配置字段写入在硬件捕获/中断使能**之前**完成 → ISR 触发即见到完整配置，ISR 侧无需锁。
3. 状态机运行时检查（如 `Icu_PriParamRuntimeCheck(ICU_CH_STATUS_STOPPED != ...)`）**不是同步机制**，只是捕获 API 使用错误；在"检查状态 → 硬件操作 → 更新状态"之间仍不做同步，其安全性依赖"ISR 不修改 ChannelStatus + 同通道 API 不重入契约"。

## 临界区使用规范（任务级需要保护处）

- 范围尽可能小：只包非原子操作本身，不包裹硬件操作、用户回调、耗时路径。
- 同一共享变量（共享资源）的所有保护点使用**同一种**临界区接口（如 `SchM_Enter_Icu_ICU_EXCLUSIVE_AREA_XX` / `SchM_Exit_Icu_ICU_EXCLUSIVE_AREA_XX`）。
- Enter/Exit 必须严格配对，不得跨 if/else 分支、不得跨 return。
- 若条件分支在不同分支都要更新资源，先进入临界区→更新→退出，或统一结构保证每分支成对。
- 可在临界区内只读取共享值到局部变量，立即退出，再用局部变量做后续判断（缩小持有时间）。

## 输出格式

先输出分析结论表，再实施修改：

| 全局变量 | 访问点 | 上下文 | 操作形态 | 是否需要临界区 | 理由 |
|---|---|---|---|---|---|
| ... | ... | API/ISR/多核 | 原子/非原子/跨行 | 是/否 | 一句话理由 |

修改完用诊断和 grep 验证 Enter/Exit 配对数。
