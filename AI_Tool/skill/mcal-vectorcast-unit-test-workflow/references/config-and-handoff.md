# 配置、XLSX 与人工交接契约

## EB 工程

- 工程目录和 `.project` 名为 `<Module>_EB_ConfigN`，保留模块大小写与已批准编号，不用 A/B、日期或 copy/final 后缀。
- 从同平台有效模板复制，核对 `.project`、`.prefs`、`.xdm` 模块版本、插件注册、路径和资源引用。已有非标准目录不自动迁移。
- `output/` 只由 EB 实际生成；`.metadata` 和 TDB 由工具管理，不编辑或复制 TDB 来假冒导入。
- 运行前发现本机 EB 版本、实际入口、有效模板及命令帮助，不能照抄未经核实的路径或 CLI 参数；实际命令以本机工具证据为准。
- XML 可解析只证明静态结构，不证明 EB 校验、生成或 GUI 成功。记录每 Config 的实际命令、退出码、Errors、Warnings、日志路径，并核验输出新鲜度及宏值。
- PB、多 partition 不等于真实多 variant；验证 schema 支持、真实配置差异和生成符号。导入工程不等于系统模型已刷新；按实际导入器流程完成导入、校验、生成。
- 多核核对 EcuC core/partition、Base physical、Os 引用、device/channel/HW owner 与 Platform ISR；DMA 枚举、资源分配按 schema 核实。
- 不改生成器或放宽校验以制造成功；失败配置记录阻塞，独立配置可继续，整体交付标明部分完成。

## XLSX 三表结构

### Sheet1：宏状态矩阵

- A 留白；`B1:D1` 合并为“宏”，`E1:G1` 合并为“状态值”，`H1:H2` 为“测试例程”，`I1:I2` 为“备注”。
- B2:G2 为一级宏、二级宏、三级宏、一级状态、二级状态、三级状态。
- 第 3 行起填数据；同一宏关系跨 Config 时，对相同关系内容的 B/C/D/I 纵向合并，E/F/G/H 每 Config 一行。差异备注不能因合并丢失，放 Sheet3 并建立引用。
- B:I 细黑边框、等线 11、白底加粗表头、自动换行。建议列宽 B/C/D=30/28/20、E/F/G=13、H=31、I=72，随内容调整行高。
- 筛选仅在无合并区域设置，不与合并单元格冲突。
- 固定 `_VCAST_MINGW_C` 已定义、PERF OFF 也记录，注明不参与组合扩展。父 OFF 的子分支在备注/证据表标 N/A，状态格保留真实生成值。
- H 用 Config/测试例程标识关联配置；TST 尚未生成时标“待生成”，不编造用例路径。

### Sheet2：配置总览

至少含配置工程、变体、模式、核/实例、主开关向量、PB 运行时差异、EB 状态、VCAST 环境/Unit、TST 路径与生成状态、静态检查状态、人工导入/编译/执行状态、覆盖验证状态。

“是否多变体”是一级配置维度，不当成 C 宏。环境名未知填待提供，不从 EB 工程名推定。EB 成功不联动标记 VCAST 成功。

### Sheet3：证据与覆盖缺口

记录源码/schema/生成文件及行号、编译参数证据、真实宏值、N/A 原因、固定约束排除项、不可达约束、合并理由和未覆盖分支。按需记录 Config→Unit→函数→Decision/Condition→用例对、私有函数间接覆盖限制和人工报告来源。

生成后重新打开 XLSX 核验三表、合并范围、内容完整性和样式；真实生成值未获得时明确标“计划值/待生成”，不伪装成实测。

## ENV/MFG/CFG 环境文件

- 按用户阶段单独交付，不因生成环境文件而自动生成 TST、导入、编译、执行 VCAST。
- 先读取真实同环境样例，依据内容而不是扩展名判断职责；例如已证实的 CFG 可为 XML `manage-config-options`，MFG 可为 `C_DEFINE_LIST`/`C_EDG_FLAGS` 纯文本。不得硬编码为所有版本格式，也不得把 CFG 与 MFG 的内容机械同步。
- CFG 的源/include 清单从当前源码、递归依赖与匹配 EB 实际输出取得；生成 include 必须在可能同名的插件模板之前。缺失生成物只能运行匹配 EB 实际生成补齐，不能借旧 Polyspace output 或手写。
- 记录本机生成根、内网部署配置根、驱动根及 VCAST 环境根。用户明确的内网路径在本机不存在时，通过映射到已确认本机源/生成输出验证，不作为本机缺失误报。
- 写前基线备份保留字节/hash/编码/换行，避免覆盖；备份目录由用户/工程策略决定。保留实际命令、退出码、Errors/Warnings 及日志；不另建空报告树。
- 具体 ENV prefix、寄存器、回调、stub 门禁和静态检查见 `environment-files.md`。

## 人工验证交接

交付时提供实际 Config、源码版本或 hash、生成配置/宏约束、TST 路径及 hash/版本、静态检查结论和已知缺口。清单可在回复或既有交付文档中给出，不额外创建空报告树。

请内网人工：

1. 建立/核对 VectorCAST 环境、工具版本、Unit、源清单、include 顺序、桩与私有函数访问设置。
2. 确认实际编译定义 `_VCAST_MINGW_C`，全部相关 PERF 宏处于关闭状态，并与对应 Config 的其余宏一致。
3. 导入 TST，检查丢失/拒绝的用例及路径解析错误；编译并记录完整错误位置与上下文。
4. 执行用例，检查异常退出、卡死、用例顺序依赖、期望不匹配及重复执行稳定性。
5. 导出用例结果和函数、语句/分支、Condition/MC/DC 等约定指标的报告，包含未覆盖项及排除依据。
6. 回传 Config、环境/工具版本、源码及配置版本、所运行 TST 版本、导入/编译日志、失败用例的预期与实际值、覆盖报告。

只有实际回传报告支持的项才能标“人工验证通过/实际已覆盖”。缺报告时保持待验证；源码、配置或 TST 变更后旧报告作为历史证据，不自动适用于新版本。
