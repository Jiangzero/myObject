# MCAL VectorCAST 单元测试 Skill 使用说明

本说明面向收到此文件夹的使用者，适用于 OpenCode、TRAE 及其他能读取项目文件的 AI Agent。不要求使用同一种 AI 工具。

## 1. 这是什么，能做什么

Skill 是一组给 AI 阅读并遵循的工作规范、参考资料和模板，**不是 VectorCAST 插件，也不是安装后自动运行的测试程序**。

可以按阶段让 AI 协助：

| 阶段 | 主要工作与产物 |
|---|---|
| 宏规划 | 分析源码与配置约束，规划最小有效配置集，生成 XLSX 矩阵 |
| EB 工程 | 创建、校验并实际生成 EB tresos 配置，回填真实宏状态 |
| 环境准备 | 根据真实样例准备或适配 ENV/MFG/CFG 文件 |
| TST 生成 | 按指定函数、Unit 或模块生成/维护 `.tst`，进行静态检查 |
| 人工反馈回补 | 分析内网导入、编译、执行和覆盖报告，修正对应文件 |

本工作流固定定义 `_VCAST_MINGW_C`，相关 PERF 性能宏始终关闭，不为这两个约束扩展 ON/OFF 组合。定义的具体取值及关闭方式仍需核对源码和真实环境。

**AI 不自动运行 VectorCAST。导入、环境构建、编译、执行和实际覆盖率验证由内网人工完成。** 每次只执行用户指定的阶段，不会因生成矩阵自动接着创建全部工程。

## 2. 文件完整性

整个 `mcal-vectorcast-unit-test-workflow` 文件夹。其引用的规则和模板同样必需。

```text
mcal-vectorcast-unit-test-workflow/
├── README.md                             本使用说明
├── SKILL.md                              AI 工作流入口
├── references/
│   ├── config-and-handoff.md              配置、矩阵与人工交接
│   ├── environment-files.md               环境文件规则
│   ├── environment-templates.md           环境模板说明
│   ├── tst-rules.md                       TST 规则与原始参考修正
│   ├── dio-case-study.md                  Dio 案例，不能照搬到其他模块
│   ├── gen-vectorcast-tests.prompt.md     原始生成参考
│   └── vectorcast-tst.instructions.md     原始语法与经验参考
└── templates/
    ├── environment.cfg.template
    ├── environment.mfg.template
    └── environment.env.template
```

本包已经包含借鉴的 EB、宏矩阵规则。驱动源码、EB 工具与插件、实际项目配置和 VectorCAST 环境样例不包含在本包中，需按任务提供。

本 README 是上手指南，详细规则以 `SKILL.md` 和其指定的参考为准。原始参考存在历史示例及已修正项，不应脱离 `tst-rules.md` 单独使用。

## 3. 如何让不同 AI 工具使用

### 方式 A：通用文件加载，适用于 TRAE 和其他 Agent

这是不依赖工具原生 Skill 功能的使用方式：

1. 解压到 AI 可以读取的位置，例如项目内 `ai-guides/mcal-vectorcast-unit-test-workflow/`。
2. 用 AI 工具打开目标项目；确认它能读取该目录及需要分析的驱动源码。
3. 在对话中发送下面的启动提示词。若工具支持文件引用或附件，可同时选择 `SKILL.md`；具体入口以所用工具版本为准。
4. AI 应继续读取当前阶段所需的 `references/` 和模板，而不是只看入口文件。

可复制的启动提示词：

```text
请读取并遵循以下工作流：
<skill实际路径>/SKILL.md

将相对引用路径按该 SKILL.md 所在目录解析，并读取本次阶段要求的
references 文件；需要环境模板时再读取 templates。
不要只根据文件名或简介推断规则。若无法访问文件，请告诉我缺少哪些内容。

先简要确认你已读取的规则文件和本次执行边界。
本次只执行【宏规划 / EB生成 / ENV-MFG-CFG准备 / TST生成 / 反馈修正】中的：<填写>。
固定定义 _VCAST_MINGW_C，PERF 始终关闭，不自动运行 VectorCAST。
缺少影响正确性的必要信息先询问，不把静态检查当成运行通过。

以下是本次项目资料：
<按下一节填写>
```

**TRAE 使用要点：**可采用上述“项目文件 + 明确读取指令”方式，也可使用下方方式 B 的 `.trae/skills/` 原生目录。若所用版本未识别原生 Skill，仍可使用方式 A。

对于只能上传文件、不能访问本地目录的聊天工具，需要上传入口和本阶段全部引用资料，以及相关源码/配置片段；缺少文件系统、命令执行或 XLSX 写入能力时，只能完成相应分析或文本准备，不能声称已经本地生成工程或表格。

### 方式 B：各工具原生 Skill

将**整个 `mcal-vectorcast-unit-test-workflow` 文件夹**复制到所用工具的 Skills 目录。通常选择用户级或项目级其中一种即可：用户级供本人跨项目使用，项目级随当前项目使用。

下表是本 Skill 的完整目录，其内部必须直接包含 `SKILL.md`、`references/` 和 `templates/`，不要多嵌套一层同名文件夹。

| 工具 | 用户级目录（跨项目） | 项目级目录 |
|---|---|---|
| OpenCode | `~/.config/opencode/skills/mcal-vectorcast-unit-test-workflow/` | `<项目根>/.opencode/skills/mcal-vectorcast-unit-test-workflow/` |
| Claude Code | `~/.claude/skills/mcal-vectorcast-unit-test-workflow/` | `<项目根>/.claude/skills/mcal-vectorcast-unit-test-workflow/` |
| Codex | `~/.agents/skills/mcal-vectorcast-unit-test-workflow/` | `<项目根>/.agents/skills/mcal-vectorcast-unit-test-workflow/` |
| TRAE IDE | `~/.trae/skills/mcal-vectorcast-unit-test-workflow/` | `<项目根>/.trae/skills/mcal-vectorcast-unit-test-workflow/` |

`~` 表示运行该工具的用户主目录。Windows 通常为 `C:\Users\<用户名>`；macOS 通常为 `/Users/<用户名>`；Linux 通常为 `/home/<用户名>`。若工具运行于 WSL、远程开发机或容器，应放在该运行环境可发现的目录，而不是默认使用 Windows 主机的用户目录。

#### 加载与调用

复制完成后，在对应项目中开始会话并明确请求：

```text
/mcal-vectorcast-unit-test-workflow 
本次只为 <模块> 执行 <阶段>，如果有不确定事项先行询问再进行修改，项目模块路径资料如下：……
```

### 路径注意事项

本包出现的 `D:/MBS_Test_Project/am/...`、Dio 路径和特定工具链信息是原项目上下文或案例，**接收者必须提供自己的路径、模块和版本**，不能直接照搬。

新项目可采用以下布局，已有工程布局应先确认再处理：

```text
<ConfigRoot>/<Module>/Configs/<Module>_EB_Config1/
<ConfigRoot>/<Module>/Configs/<Module>_EB_Config2/
<ConfigRoot>/<Module>/<Module>_Macro_Config_Matrix.xlsx
```

Config 数量由有效覆盖需要决定，不固定为两套。环境文件和 TST 的目标位置另行明确，不根据 EB 工程名猜环境名或 Unit。

本机路径与内网部署路径可以不同，应明确映射。内网路径在本机不可访问，不等于内网缺文件；也不等于该路径已经验证可用。

## 5. 分阶段使用示例

以下提示词均以已经加载 Skill 为前提；将 `<...>` 替换成实际值。

### 5.1 先做宏规划和 XLSX

```text
请按此 skill，为 <模块> 分析宏关系和最小有效配置组合。
源码/插件：<路径及版本>
配置根：<路径>

本次只生成 XLSX 计划矩阵，包含宏状态矩阵、配置总览、证据与覆盖缺口。
固定 _VCAST_MINGW_C 已定义、PERF 关闭，其余组合按源码与 schema 分析。
给出每个 Config 的不可替代目标，完成后等我确认再创建 EB 工程。
```

预期得到：XLSX 计划矩阵、配置数量依据和需要确认的约束；尚未实际生成的宏值标为计划值。

### 5.2 按已确认矩阵创建并生成 EB

```text
我确认 <矩阵路径/版本> 中的 Config 规划。
请基于 <有效模板>，为 <模块> 创建对应 EB 工程，执行校验和生成。
EB 路径/版本：<填写>
允许写入：<配置根>

生成后核对真实宏、回填 XLSX，报告每个 Config 的命令、结果和 warnings。
本次到 EB 交付为止。
```

预期得到：真实 EB 工程、实际生成产物、回填矩阵和阶段结果。仅 XML 可解析不代表 EB 成功。

### 5.3 准备 ENV/MFG/CFG

```text
请为 <模块/Config> 准备 ENV/MFG/CFG。
同版本真实环境样例：<路径>
对应 EB 输出：<路径>
驱动源码：<路径>
工具链与 VectorCAST 版本：<填写>
环境名及输出目录：<填写>
本机到内网的路径映射：<填写>

请按真实依赖、寄存器访问和桩需求适配模板，完成静态检查。
不要照搬 Dio 专用寄存器、回调或 Unit；不要自动运行 VectorCAST。
```

预期得到：环境文件、依赖/路径检查结果和待内网确认项。模板中的占位符必须处理，模板不是直接可导入的成品。

### 5.4 生成或追加 TST

```text
请为 <Config> 的 <Unit/函数范围> 生成 TST。
源码、生成配置和环境文件：<路径>
真实导出样例：<路径>
目标 TST：<路径>
已有用例/场景编号：<填写>
新场景起始编号：<填写>

按当前有效编译分支设计正常、边界、错误码和 MC/DC 用例。
所有可达错误码独立触发并分别断言，只设置场景及隔离所需的有效参数。
已有 TST 默认仅追加；如需修改旧例，先说明原因和范围。
同模块相同场景跨 Config 复用编号，配置特有场景新增编号。
完成静态自检后交付，并明确哪些仍待人工验证。
```

编号规则：单份 TST 内名称唯一；跨 Config 的相同场景复用编号，因此单个配置可以有编号缺口。不要给每个 Config 从上一配置的末尾继续编号。

**没有导出样例怎么办？** 默认先补充必要证据。如果希望先产出候选稿，可明确授权：

```text
我明确授权基于真实源码和现有 ENV 先生成候选 TST。
缺少导出样例或未确认符号路径的部分，请标明推断依据和未验证项。
这次交付是待内网验证的候选稿，不得声明可导入、可编译或已覆盖。
```

候选模式允许带明确标注的推断，不允许编造源码、配置值或执行结果。

### 5.5 用人工结果修正

```text
这是 <Config/环境> 的内网验证结果。
实际运行的源码/配置版本：<填写>
TST 版本或 hash：<填写>
导入/编译日志：<文件>
失败用例与实际值：<文件>
覆盖报告及未覆盖明细：<文件>

请先定位原因，再在 <允许修改的文件范围> 内修正。
保留已有场景编号与追溯关系，只对报告对应的版本更新验证状态。
完成后列出需要人工重新导入、构建或执行的步骤，不自动运行 VCAST。
```

## 6. 人工如何完成验证闭环

1. 将对应配置的生成代码、环境文件和 TST 按内网路径部署。
2. 核对工具版本、Unit、源清单、include 顺序及实际生效的宏；确认 `_VCAST_MINGW_C` 已定义且 PERF 关闭。
3. 创建或更新环境并构建。**修改 ENV/MFG/CFG 后，仅重新导入 TST 不足以更新环境。**
4. 导入 TST，记录拒绝导入或解析失败的用例；编译并执行，检查断言、异常退出、卡死和顺序依赖。
5. 导出测试结果和约定的覆盖报告，记录源码、Config、环境及 TST 版本。
6. 将错误日志和未覆盖明细交给 AI 增量修正，重新验证受影响项。

区分以下结论：

- **已生成**：文件已写出。
- **静态检查通过**：完成列明的文本、路径或源码一致性检查。
- **人工执行通过**：有对应版本的实际执行结果支持。
- **覆盖达标**：有对应配置与版本的覆盖报告支持。

前两项不能替代后两项。生成了 MC/DC 用例不等于已经达到 MC/DC 覆盖率。

## 7. 常见问题

**AI 说没有这个 Skill？** 直接提供 `SKILL.md` 的真实路径并要求读取；若仍不能读，检查工作区范围或上传当前阶段必需文件。

**可以只把两份原始 TST 参考发给 AI 吗？** 不建议。修正规则、环境约束、编号规则及人工验证边界也必须一起加载。

**是否必须安装 EB 和 VectorCAST？** 只做源码分析或 TST 文本准备不一定需要本机工具；实际 EB 生成需要可用的 EB、插件和相应运行条件。VectorCAST 验证在内网人工环境完成。

**AI 无法写 XLSX 或执行 EB 怎么办？** 让它明确报告能力缺口；补齐执行/文件写入能力或由人工完成对应动作。不能用文字声称已生成实际不存在的表格或工程。

**能否直接把 Dio 案例用于其他模块？** 案例仅供方法参考。Unit、寄存器、回调、类型、错误码及依赖必须重新核对当前模块。

**换会话或换 AI 工具后怎么办？** 重新加载 Skill，并提供已确认矩阵、当前阶段、文件路径和最新人工反馈。不要依赖另一个会话记住授权和配置。
