# TT_CodeCheck — 代码检查 Skill

按以下 10 个维度逐项审查待测代码。每项标注 ✓（通过）、✗（不通过+说明）、—（不适用）。

## 一、代码风格

1. 文件命名、函数命名、变量定义及其存放位置是否合理
2. 文件之间包含关系是否有嵌套
3. 文件注释是否使用 `/* */` 方式进行，函数的注释说明是否有错误（代码与注释不一致、函数定义注释与声明注释不一致）
4. 参数、返回值检查及错误码上报是否与 AutoSar 规范一致？错误码是否有重复上报
5. 非 AUTOSAR 接口若有返回值则应为 `TT_RetType`（私有函数可根据实际情况设计，无正确性检查可无需返回值）
6. 代码语句是否对齐？源码与生成代码要求 4 个空格代替一个 tab
7. 是否删除了多余空行？最多保留一行空行
8. 源码最后是否有空一行

## 二、数据类型

9. 数据类型中的所有成员是否有注释说明
10. 是否有未使用的数据类型定义
11. 是否有相似的数据类型定义，能否融合
12. 数据类型名是否不超过 32 个字符
13. 结构和联合体的最后一个成员不应该有逗号
14. 枚举成员的命名是否带模块名

## 三、宏定义

15. 宏定义是否对齐，格式是否美观
16. 宏定义的命名是否带模块名
17. 带逻辑的宏内容是否在 `()` 内
18. 宏定义的命名和注释是否详细描述宏定义作用或宏定义值
19. 是否定义了未使用的宏定义
20. 宏定义名称是否不超过 32 个字符
21. 宏的使用（包括预编译宏）是否正确？自定义/界面生成的宏在使用时是否曲解其含义？预编译逻辑有无异常，宏是否包错了地方

## 四、函数

22. 函数名称是否不超过 32 个字符
23. 函数命名是否以文件名作为开头
24. MCAL/BSP 层的函数是否与 BSP/MCAL 隔离开？（包括数据类型、变量、宏定义）
25. 单个函数是否不超过 200 行
26. 关键代码是否有注释
27. 局部变量是否定义在函数起始处且赋初始值
28. 函数内部逻辑是否有误
29. 函数传参是否合理？（参数不会被使用？参数个数 <= 5 个）
30. 是否有相似功能的函数，能否合并？相同功能的代码块能否提取为函数
31. **★参数检查逻辑是否正确？**
    - 参数使用前是否进行了合理化检查？是否遵循哪里用到哪里再检查的原则？
    - MCAL/Drv 层需自定义检查函数，需被 ErrorDetect 和 `TT_PERF` 包围；HW 层统一通过 `TT_ParaCheck` 检查（inline/static 本地函数可不做）
    - 指针类型参数是否先检查空指针？
    - 数组类型参数是否先检查下标是否越界？
    - 范围检查应确认 ≤/≥/==/!= 是否有混淆
    - 是否存在错误码覆盖问题
32. 中断服务函数操作流程是否正确？进中断后先清中断标志；回调函数必须在清中断标志及更新软件状态后；状态是否需要通过回调函数传递参数给用户
33. static 函数是否在文件前面声明、文件后面实现
34. 是否存在不必要的 barrier 指令
35. 是否对返回值进行判断？调用函数时对其返回值做正确性判断；参数检查的返回值是否有判断；函数内部 return 的错误码是否存在被覆盖情况
36. 函数是否符合所定义的重入性设计
37. 不同编译链下的与编译链强相关的操作是否正确？（语法、汇编、内建函数，如 Base 模块的原子操作）
38. 访问指针内容时是否事先检查指针合法性？赋值给指针时是否确认所赋值是预期地址
39. 数组下标索引使用是否正确？循环中是否会超出索引范围（下标索引为预期硬件 ID / 逻辑 ID 等）
40. 是否存在冗余逻辑？（冗余的参数检查、范围限制、死代码）
41. 解锁/上锁等成对逻辑是否有遗漏
42. 写 1 清、读清、只读、只写寄存器的操作是否合法
43. 使用寄存器/变量进行判断或写入（与/或方式）时是否对无效区域进行掩码
44. Mcal 层获取 bsp 层返回的错误码时，是否考虑 bsp 层错误码变量是拼接后的特性？若只为获取错误码应屏蔽其他拼接位域
45. 寄存器操作上下文顺序是否有影响？先确定中断模式再使能中断；先关闭中断再清除中断模式；先配置中断状态再使能中断；关闭时先关闭再配置
46. 寄存器配置的掩码宏使用是否无误？位移操作是否无误？
47. 类型强转是否正确？强转赋值时是否会发生溢出/超限/丢失
48. 操作的寄存器是否为预期硬件单元或通道寄存器？指向寄存器的指针是否正确？资源数组下标索引是否正确
49. 等于/与等于/或等于/与/或 等逻辑是否正确？等于会否覆盖其他位域修改？与等于/或等于是否混淆？写 1 清不能用或等于。与/或逻辑是否混淆
50. 函数形参检查：传入的指针参数使用是否正确（储存符号 vs 指向数据）？调用函数时参数传入是否正确，是否是形参预期数据
51. 循环语句的退出机制是否可能存在异常不满足情况
52. 代码中不应该直接使用数字，应该使用宏或变量

## 五、全局变量

53. 变量名是否不超过 63 个字符？函数和变量名称前 32 个字符不得相同
54. 所有全局变量是否有注释描述
55. 全局变量是否是最小作用范围？（改为静态或局部变量，减少全局变量直接参与函数内部运算的方式更新该变量）
56. 数据是否不存在隐藏的数据流或控制流
57. 变量是否有对齐需求？（DMA 数据要对齐；cache 操作地址要对齐；非对齐操作如 uint32 但地址没按 32bit 对齐）

## 六、变量修饰

58. 使用过程中没有修改的变量是否加 `const` 修饰
59. 全局变量声明是否加 `extern` 修饰（函数 .h 声明编译器默认加 extern）
60. 仅模块内使用的变量和函数是否加 `static` 修饰
61. 多任务调用或防止被优化的变量是否加 `volatile` 修饰（多线程共享资源）
62. 不得直接使用 `int`、`unsigned int`、`const` 等关键字，需使用 typedef 后的类型

## 七、标准及功能

63. 代码中不得有 `print` 等调试信息

## 八、配置界面

64. IDE 的注释、Table、错误提示是否完全汉化
65. 参数间有关联的（A <= B），检查配置逻辑是否正确，配置错误是否能报错
66. 中英文注解含义是否正确，语句是否通顺，无错别字
67. 英文缩写是否正确且注释按单词隔开
68. 界面生成是否符合预期？
    - 列表顺序与实际生成的索引是否正确
    - 宏/变量的生成是否和界面内容一致
    - 界面直接关联逻辑是否同设计文档中的配置依赖项保持一致
    - 界面配置范围报错/下拉限制是否同组件设计文档一致，默认配置生成是否正确
    - 能修改名称的组件，对其进行修改检查
69. postbuild/precompile 下生成的结构体命名是否正确？应按 `模块名_Config` 形式（如 `Mcu_Config`、`Stm_Drv_Config`）。postbuild 模式下应可修改名称

## 九、工程

70. MCAL/BSP 工程能否编译通过且没有警告（Hightec、GCC、LLVM、ghs）

## 十、注意事项

71. 确认 SVD / 寄存器头文件是否正确（模块基地址、寄存器名称、寄存器位域）
72. 考虑去初始化后再初始化运行的场景是否正常？寄存器默认值对驱动是否有影响

## 十一、高级功能

76. 模块使用的 RAM 是否初始化后再使用
77. SafetyLib 不应直接引用 Mcal/Bsp 的结构体变量（考虑 SafetyLib 的独立性）
78. 是否合理使用 memmap 和数据代码指向？（热点函数/变量应放在 fast 段；多核下变量和函数注意核分区）
79. 是否合理使用了临界区保护？
    - 检查全局变量和模块寄存器及其作用域是否需要临界区保护
    - 检查可重入函数是否需要临界区保护相关代码数据
    - 临界区使用是否成对
    - 临界区实现是否考虑嵌套功能
    - 临界区保护内容是否有注释说明
80. 是否确认基础配置下 CRC 校验逻辑正确？（界面 CRC 计算使用的数据和生成文件生成的数据是否一致，如界面只读计算了真实数据的 CRC，但生成文件的数据却是默认值）
81. 配置项是否区分 precompile 和 postbuild？规范组件对照 MCAL 规范文档检查属性是否正确；CDD 模块需考虑生成的变量是否需要被 postbuild 下修改
82. MTL 的所有自测试功能是否兼容模块寄存器变化、模块使能、各硬件单元单独使能？MTL 各模块测试项代码各模块负责人是否确认无误
83. 代码中计算公式是否考虑变量（如分子分母）为 0 的处理？计算公式中变量是否是预期变量？计算公式是否有补充注释说明
84. 多核场景下交互的地址指向是否一致（各方看到的地址是否相同）
85. 状态改变后的操作应明确识别该状态是否达成（如 I2C 发送结束通过判断硬件 stop 状态位置位再关闭使能，而非中断结束就关闭；UART 发送应判断 FIFO 状态再下一步）
86. **★模块状态信息是否能被外界感知？** 错误状态寄存器中的状态值是否需要被用户感知，通过接口获取还是回调函数通知
87. InitCheck 检查内容是否与初始化配置逻辑保持一致？初始配置时宏屏蔽或 if 判断逻辑应与 InitCheck 保持一致
88. 操作内存时是否有考虑 cache 一致性检查
89. 时钟分频的操作是否在对应时钟使能之前进行
90. 模块的初始化驱动中不应调用所依赖模块的初始化接口
